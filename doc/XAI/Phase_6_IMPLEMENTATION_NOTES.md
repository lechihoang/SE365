## 2. Proposal Deviations

### 2.1 Single module instead of 5 separate files

- **Proposal:** Create `case_study_selector.py`, `case_study_figure.py`, `case_study_metadata.py`, `case_study_analysis.py`, `case_study_runner.py`.
- **Actual:** Single consolidated `xai/case_study.py`.
- **Why:** Phases 2-5 each have ONE module (gradcam_explainer.py, attention_explainer.py, shap_explainer.py, lime_explainer.py). Following this established pattern is more consistent. The 5-file split would be unique and increase import complexity for downstream phases.

### 2.2 Simplified conflict detection

- **Proposal:** Complex signed SHAP + keyword heuristic with Vietnamese sentiment lists.
- **Actual:** Simplified to: samples with high error AND SHAP showing one modality dominant.
- **Why:** Full Vietnamese sentiment keyword matching requires extensive NLP processing. The simplified approach captures the most important conflict signal (high prediction error + modality imbalance) and is more robust.

### 2.3 Combined figure layout

- **Proposal:** 12×14 inches with 6 detailed panels.
- **Actual:** 12×12 inches with 3 rows × 2 columns, streamlined layout.
- **Why:** 14 inches is very tall for a single thesis figure. The streamlined layout fits better in thesis pages while retaining all 4 XAI methods.

## 3. Technical Decisions

### 3.1 Orchestrator architecture (upgraded from pure consumer)
Phase 6 now operates in two modes:
- **Consumer mode** (`model=None`): reads existing artifacts only, shows placeholders for missing ones. Backward compatible with original design.
- **Orchestrator mode** (`model` provided): automatically generates missing XAI artifacts by calling Phase 2-5 explainer modules on-demand. This ensures every selected case study has complete multi-method explanations.

The `XAIOrchestrator` class lazily initializes explainers from Phases 2-5 and calls them only when artifacts are missing. It uses cache-first logic: existing artifacts are never regenerated.

### 3.2 Artifact loading via PIL
Combined figures are assembled by loading saved PNG images via PIL.Image.open() and displaying them in matplotlib subplots. This avoids recomputing any XAI outputs.

### 3.3 Progressive threshold relaxation
Each case type selector starts with strict thresholds and relaxes progressively if too few candidates are found. The final thresholds used are recorded in `selection_log.json`.

### 3.4 De-duplication priority
If a sample qualifies for multiple case types, it's assigned to the highest-priority type: conflict > high_error > text_dominant > image_dominant > difficult > agreement > correct.

## 4. Assumptions

- Previous phases (2-5) have been run for at least 5-15 samples
- Artifacts follow the `{phase_dir}/{sample_id}/` subdirectory pattern
- SHAP contribution JSON has per-factor `text_pct` and `image_pct` keys
- Prediction CSV has columns: `y_true_{factor}`, `y_pred_{factor}`, `absolute_error_{factor}`
- Dataset CSV has columns: `comment_clean`, `image_url`

## 8. V2 Changes — Cross-Attention Integration

### 8.1 What changed

| Area | V1 | V2 |
|---|---|---|
| Artifact checking | 4 phases (GC, AT, SHAP, LIME) | 5 phases (+Cross-Attention) |
| Completeness score | `found / 4` | `found / 5` |
| Selection scoring | No cross-attention factor | 1.2× boost for cross-attention availability |
| Orchestrator | 4 generators | 5 generators (+`_generate_cross_attention`) |
| Combined figures | 1 figure type (core) | 2 figure types (core + cross-attention) |
| Metadata | 4 phase availability fields | 5 phase availability fields |
| Analysis text | No cross-attention section | Cross-attention interpretation section |
| Notebook artifact table | GC/AT/SH/LM columns | GC/AT/CA/SH/LM columns |
| Notebook validation | Checks core figure only | Checks core + cross-attention figures |

### 8.2 Cross-attention combined figure

Each case study now generates a separate `combined_cross_attention_figure.png` (14×16 inches) containing:
- Original image + patch importance overlay
- Top tokens → patch overlay grid (full row)
- Top-K token × patch heatmap + bipartite graph

This avoids overcrowding the core figure while giving cross-attention its own thesis-quality presentation.

### 8.3 On-demand cross-attention generation

`XAIOrchestrator` now includes `_generate_cross_attention()` which initializes `CrossAttentionExplainer` lazily and generates the full token-patch visualization suite (overlays, heatmaps, bipartite graph) for missing samples.

## 9. Known Limitations

1. **Conflict detection is simplified** — does not use full Vietnamese sentiment analysis. Manual review of conflict candidates is recommended.
2. **Figure layout is fixed** — does not adapt dynamically to different numbers of available artifacts.
3. **Keyword-based text analysis** — the "difficult" case detector uses simple keyword presence/absence, which may miss complex linguistic patterns.
4. **Cross-attention figure requires images** — if `loaded_images` is empty for a sample, token→patch overlays cannot be generated.

## 10. How to Verify

1. Run the notebook end-to-end on Colab
2. Check that `case_study_index.csv` contains 10-17 rows
3. Verify each case directory has `metadata.json` and `analysis.md`
4. Open combined figures (core + cross-attention) and verify panels are populated or show placeholders
5. Check `selection_log.json` for threshold decisions
6. Verify `sample_manifest.csv` contains all selected sample data
7. Check per-case validation table for core_fig/ca_fig/meta/analysis status
